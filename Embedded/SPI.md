# SPI

**SPI stands for Serial Peripheral Interface. It is a synchronous serial communication protocol used for communication between a master device and one or more slave devices.**

The main idea of SPI is that the master generates a clock signal, and data is transferred synchronously based on this clock.

SPI usually uses four communication lines:

* **SCLK (Serial Clock)**
  Clock signal generated by the master.
  It synchronizes data transmission between master and slave.
* **MOSI (Master Out Slave In)**
  Data line from master to slave.
  Used when the master sends data to the slave.
* **MISO (Master In Slave Out)**
  Data line from slave to master.
  Used when the slave sends data back to the master.
* **CS/SS (Chip Select / Slave Select)**
  Used by the master to select which slave device it wants to communicate with.
  Usually active low.

---

### How SPI works

When the master wants to communicate with a slave:

1. The master pulls the slave's CS line low to select that device.
2. The master generates the clock signal on SCLK.
3. On every clock cycle:
   * The master sends data through MOSI.
   * The slave sends data through MISO.
4. After finishing communication, the master releases CS back to high.

SPI supports **full-duplex** communication, which means the master and slave can transmit and receive data at the same time.

For example:
During one clock cycle:
* Master sends bit 1 through MOSI.
* Slave sends bit 1 through MISO simultaneously.

---

### SPI Clock Modes

SPI has four clock modes, defined by two parameters:

* **CPOL (Clock Polarity):**
  Defines the idle state of the clock.
  * CPOL = 0 → clock idle low.
  * CPOL = 1 → clock idle high.
* **CPHA (Clock Phase):**
  Defines whether data is sampled on the first or second clock edge.

The combination of CPOL and CPHA gives:

| Mode | CPOL | CPHA |
|------|------|------|
| Mode 0 | 0 | 0 |
| Mode 1 | 0 | 1 |
| Mode 2 | 1 | 0 |
| Mode 3 | 1 | 1 |

The master and slave must use the same SPI mode, otherwise data will be corrupted.

---

### SPI vs UART

| Feature | SPI | UART |
|---------|-----|------|
| **Type** | Synchronous | Asynchronous |
| **Clock Signal** | Uses clock signal | No clock signal |
| **Speed** | Faster | Slower |
| **Duplex** | Full duplex | Usually full duplex |
| **Wiring** | Requires more wires | Requires fewer wires |
| **Topology** | Supports multiple slaves | Point-to-point communication |

---

### SPI vs I2C

| Feature | SPI | I2C |
|---------|-----|-----|
| **Wiring** | More wires (4+) | Only 2 wires |
| **Speed** | Higher speed | Lower speed |
| **Duplex** | Full duplex | Half duplex |
| **Addressing**| No addressing, uses CS | Uses device address |
| **Scalability**| More GPIO required | More scalable |

---

### Example in Embedded System

A common example is communicating with an external sensor or memory:

```text
        SPI Master (MCU)
              |
       ----------------
       |      |       |
      SCLK   MOSI   MISO
              |
             CS
              |
        SPI Slave (Flash Memory)
```

For example, when reading data from an external Flash:

1. MCU pulls CS low.
2. MCU sends a READ command through MOSI.
3. Flash returns data through MISO.
4. MCU receives the data.
5. MCU releases CS.

### Interview short answer

> "SPI is a synchronous serial communication protocol used for high-speed communication between a master and slave device. It uses four signals: SCLK, MOSI, MISO, and CS. The master generates the clock and controls communication by selecting the slave through CS. SPI supports full-duplex communication because data can be transmitted and received simultaneously. The main advantages of SPI are high speed and simple protocol, but it requires more GPIO pins compared with protocols like I2C."
